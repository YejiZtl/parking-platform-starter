# Parking Platform Starter

固定摄像头停车位占用检测项目：Ultralytics YOLO 负责车辆检测，人工标定的 ROI 和 122 个车位多边形负责占用判断。

维护请先阅读 [docs/MAINTENANCE.md](docs/MAINTENANCE.md)。其中记录了当前生产基线、处理链路、设计原因、服务器日常运维、训练与验证、发布回滚、已知风险和离职交接验收清单。运行参数默认值以 `parking_config.py` 为准，`.env` 和命令行只做覆盖。

## 消融实验（2026-09-05）

已完成 9 组同帧检测对照、车位匹配诊断和合成时间防抖实验，详见 [实验报告与复现说明](docs/ABLATION.md)。固定回归验证集共 6 张图、745 个车辆框，统一推理参数下 V3 精确率为 95.44%、召回率为 98.39%、暗车代理召回率为 97.40%。去掉显式去重后精确率降至 89.42%；1280 分辨率在本集总体召回持平，模型推理耗时约减少 55.9%，仍需新场景验证。

停车场智能管理项目研发记录
整理日期：2026-08-27

一、项目概述

基于固定高位摄像头的 RTSP 视频流，搭建停车场车辆检测与车位占用统计原型。系统能够定时读取实时视频、识别停车区域内车辆、判断每个车位状态，并输出可视化视频和结构化事件日志，为后续接入停车管理平台提供数据基础。

当前项目状态：
- 已完成单摄像头端到端原型。
- 已标注 122 个车位。
- 默认每 5 秒检测一次。
- 支持实时预览、录像保存、占用/空闲统计、异常流自动重连。
- 配置集中保存在环境参数文件中，提供一键启动脚本。
- 已完成面向黑色车辆和密集遮挡场景的 V3 定向训练与固定困难集回归验证。
- 已建立模型文件校验、服务器配置备份、服务重启、HLS 验证和失败回滚流程，V3 模型正在执行服务器上线验证。

二、主要技术栈

- Python
- Ultralytics YOLO
- PyTorch
- OpenCV
- RTSP 视频流
- NumPy
- Shapely
- LAP 全局匹配
- python-dotenv
- FFmpeg
- NVIDIA NVENC
- MediaMTX / HLS

三、核心处理流程

摄像头 RTSP 视频流
    -> 定时获取高清帧
    -> YOLO 车辆检测
    -> 停车场 ROI 过滤
    -> 重复检测框去重
    -> 车辆与车位多边形匹配
    -> 时间防抖与可信度判断
    -> 输出占用数、空位数、疑难车位和可视化结果

四、研发经过

1. 视频流接入

- 完成 RTSP 地址配置、摄像头连通性检查和视频帧抓取。
- 增加视频断流后的自动重连能力。
- 将实时检测频率设置为每 5 秒一次，降低 GPU 占用和无意义的重复计算。
- 推理和录像保留原始分辨率，桌面预览单独等比例缩放，解决高分辨率画面显示不全的问题。

2. 停车区域与车位标注

- 绘制停车场 ROI，过滤道路车辆和停车场外部目标。
- 完成 122 个车位多边形标注。
- 替换原始车位标注工具，开发可继续编辑的车位编辑器。
- 编辑器支持加载已有车位、全画幅缩放、四点新增、光标删除、撤销、保存和自动备份。
- 鼠标显示坐标会自动换算回摄像头原始分辨率，避免缩放造成坐标精度损失。

3. 数据采集与标注效率优化

- 从 RTSP 视频流中抽取训练图片。
- 对相似帧进行筛选，减少大量重复画面的人工标注工作。
- 开发批次式标注流程，每标注一批数据后训练模型，再用新模型预标注下一批。
- 增加标注进度记录、自动续标、光标删除错误框和 ROI 外标签过滤。
- 对训练标签进行审计，处理重复框、区域外车辆和不合理标注。

4. 自定义车辆检测模型训练

- 在通用 YOLO 权重基础上训练停车场专用单类别车辆检测模型。
- 训练轮数：25 轮。
- 最佳 Precision：95.1%。
- 最佳 Recall：95.2%。
- 最佳 mAP50：97.6%。
- 最佳 mAP50-95：91.7%。
- 最终模型约 42 MB，类别 0 表示车辆。
- 对通用中型模型和自训练模型进行同帧对比，最终选择自训练模型作为主模型。

5. 检测与占用算法优化

- 使用停车场 ROI 强制过滤道路车辆。
- 增加显式重复框过滤，通过 IoU、中心距离和框面积比例判断同一车辆的重复检测。
- 使用车辆检测框与车位多边形的中心和面积重叠关系判断占用。
- 增加占用/释放连续确认机制，降低单帧漏检导致的状态跳变。
- 将每次检测结果写入 JSONL，包括总车位、占用、空闲、原始检测数、过滤数和疑难车位编号。

6. 密集车辆与高位视角问题研究

- 发现高位斜视画面中，相邻车辆的轴对齐矩形框容易跨越两个车位。
- 实现“一车一位”的全局最优匹配算法，并使用 LAP 求解车辆与车位分配。
- 在相同实时帧上完成旧算法、新算法、通用模型、自训练模型和双模型组合对比。
- 严格一车一位模式会将约 116 个真实占用降到 104 个，说明部分密集车辆被模型合并成单个检测框，直接上线会产生明显漏报。
- 最终采用“影子审计”策略：保留更接近实际的占用统计，同时用严格匹配评估可信度。
- 高可信占用显示为绿色，空位显示为红色，仅依赖相邻框或遮挡推断的车位显示为黄色，并输出 Uncertain 数量和车位编号。
- 该方案避免为了消除少量重复而制造大规模漏报，也为后续定向补充训练数据提供依据。

7. 工程化处理

- 使用环境配置文件统一保存模型、阈值、检测间隔、ROI 和预览尺寸等参数。
- 提供一键启动停车检测、一键编辑车位和训练状态查看脚本。
- 关键覆盖操作前自动备份模型、代码、车位文件和配置。
- 输出带状态标注的视频和逐帧 JSONL 事件，便于后端或数据库继续接入。
- 未在项目文档和对外材料中保存摄像头密码、RTSP 凭据等敏感信息。

8. 黑色车辆专项优化与二次训练

- 针对黑色车辆在阴影、低对比度和密集停车区域容易漏检的问题，从实际监控画面中筛选困难样本。
- 对困难样本逐张人工复核，只保留确认无误的车辆框，避免自动预标注错误继续进入训练集。
- 基于人工核验数据训练单类别 V3 车辆检测模型，并保留旧模型作为对照和回滚版本。
- 在固定的 6 张困难图片、共 745 个车辆框上统一参数对比 V2 与 V3，暗车代理召回率由 89.4% 提升至 97.4%。该集存在祖先训练重合风险，不作为独立泛化成绩。
- 同一困难集上的整体召回率由 93.0% 提升至 98.4%，精确率由 96.8% 变化为 95.4%，体现召回与精确率的取舍。
- 在另外抽取的 18 张实时监控帧上复核，新模型每帧平均找回约 8 至 9 辆旧模型漏掉的真实车辆，新增目标主要为黑色或阴影中的车辆。
- 根据验证结果将运行参数调整为置信度 0.12、IoU 0.35、推理尺寸 1920、最大检测数 500，并继续启用重复框过滤，控制低阈值带来的重复框和误检。

9. 实时推流与服务器发布准备

- 使用独立实时脚本读取摄像头 RTSP 流，完成车辆识别、车位状态绘制和结果视频输出。
- 使用 NVIDIA NVENC 进行 H.264 硬件编码，降低实时视频编码对 CPU 的占用。
- 通过 MediaMTX 将识别结果发布为 HLS 流，供浏览器端播放器查看。
- 为 V3 模型生成独立发布包和 SHA-256 校验值，上传后必须再次校验，防止模型文件传输损坏。
- 发布前备份环境配置、当前模型路径、模型哈希和运行日志，再修改模型路径与推理参数。
- 规范服务停止、后台启动、PID 保存、日志检查、进程检查和 HLS 播放列表验证命令；新服务验证失败时恢复旧配置并重新启动旧模型。
- 当前已完成本地模型验证和发布流程准备，服务器端替换与长时间实时流观察仍需完成最终确认。

五、关键问题与解决思路

问题 1：画面分辨率高，桌面窗口显示不全。
解决：推理保持原始分辨率，仅对预览窗口等比例缩放。

问题 2：训练图片高度相似，人工逐张标注效率低。
解决：相似帧筛选、批次训练、自动预标注和进度续接。

问题 3：道路车辆被计入停车场。
解决：绘制停车场 ROI，并按车辆中心位置进行强制过滤。

问题 4：同一辆车出现多个检测框。
解决：组合 IoU、中心距离和面积比例进行显式去重。

问题 5：车辆密集、遮挡严重，矩形框可能跨越相邻车位。
解决：测试全局一车一位匹配；发现严格模式会漏报后，改为影子审计和黄色疑难位提示，避免未经验证的算法直接影响统计结果。

问题 6：状态在相邻检测周期之间跳变。
解决：使用连续检测确认和历史状态防抖，停车和释放状态不会仅凭一次异常结果立即改变。

问题 7：黑色车辆与地面、阴影对比度低，旧模型容易漏检。
解决：从实际监控画面定向收集黑车困难样本，人工复核标注后进行二次训练，并使用固定回归验证集和新抓取实时帧共同验证；当前固定集存在祖先训练重合风险，还需另建未参与训练和调参的独立测试集。

问题 8：降低置信度虽然能找回黑车，也可能增加重复框和误检。
解决：通过困难集同时比较召回率和精确率，选择 0.12 作为运行阈值，并继续使用显式重复框过滤和车位区域约束控制误报。

九、面试时可以重点讲的内容

1. 为什么普通车辆检测准确率较高，车位统计仍可能出错：检测框和车位之间还存在匹配问题。
2. 为什么没有直接上线严格的一车一位算法：离线指标和实际停车状态不同，严格规则在密集遮挡下会造成大量漏报。
3. 如何验证优化是否有效：固定同一视频帧，对旧算法、新算法和不同模型做可视化及数量对比，再用实时流观察稳定性。
4. 如何提高标注效率：去除重复帧、批量预标注、保存进度、分批训练，而不是从头人工标注全部图片。
5. 工程上如何避免实验破坏可用版本：配置文件固化参数、关键文件自动备份、保留回滚版本、实验算法先以影子模式运行。
6. 如何专项改善暗车漏检：从真实监控中筛选困难样本，人工复核标签，统一参数比较新旧模型，同时审计祖先训练数据重合、召回率提升和精确率变化，并区分固定回归验证与独立泛化测试。

本地代码实现周期检测、ROI/重复框过滤、一车一位车位匹配、状态防抖、日志轮转和健康文件。它不内置 MediaMTX/HLS/NVENC 推流；这些属于外部部署链路。

服务器是否已经运行 V3 不能从本地 `.env` 推断，必须在服务器上核实实际进程和加载模型路径。
